================================================================================
                            HOW IT WORKS
================================================================================

COMPRESSION PIPELINE:

  Input File
     ↓
  [Stage 1] Run-Length Encoding
     ├─ Detects runs of identical bytes
     ├─ Encodes as [escape_byte, byte_value, count]
     └─ Example: "AAAA" → much smaller representation
     ↓
  [Stage 2] Adaptive Huffman Encoding
     ├─ Generates variable-length binary codes
     ├─ More frequent values get shorter codes
     └─ Highly effective on RLE output
     ↓
  Compressed File (bitstream)


DECOMPRESSION PIPELINE:

  Compressed File (bitstream)
     ↓
  [Step 1] Huffman Decoding
     ├─ Reads binary codes
     └─ Generates bytes (RLE-encoded)
     ↓
  [Step 2] RLE Decoding (if needed)
     ├─ Detects RLE sequences [255, byte, count]
     ├─ Expands to original run
     └─ Auto-detected via format version
     ↓
  Output File (original)

When RLE Helps Most:
  • Log files (repeated timestamps, messages)
  • Text with patterns (repeated spaces, newlines)
  • Configuration files (repeated structure)
  • CSV data (repeated columns)

When RLE Doesn't Help:
  • Already compressed (ZIP, JPEG, MP3)
  • Random data
  • Highly varied text (like this guide)

================================================================================
                        FILE FORMAT
================================================================================

Version 2 (NEW - RLE + Huffman):
  [8 bits]  Version = 2
  [16 bits] Number of chunks
  [bits]    Huffman-encoded data (from RLE preprocessing)
  [padding] Zero-padding to byte boundary

Version 1 (ORIGINAL - Huffman only):
  [16 bits] Number of chunks
  [bits]    Huffman-encoded data
  [padding] Zero-padding to byte boundary

Auto-Detection:
  Decompressor reads first 8 bits
  If valid version identifier → Version 2
  Otherwise → Version 1
  Applies correct decompression automatically!
